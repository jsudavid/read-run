# 0001 · 使用 Cloudflare Pages 静态 HTTPS 发布

- 状态：已接受
- 日期：2026-09-28

## 背景

PRD v1.0 把 **NFR-01「离线可用」定为 P0**，并把"需要依赖网络连接"列入 **§8.3 明确不达标情形**。原始假设是教室网络不可靠，程序不得依赖互联网。

浏览器的麦克风接口 `getUserMedia` 只在安全上下文（`https://` / `localhost` / `127.0.0.1`）可用；公网 `http://` 下 `navigator.mediaDevices` 为 `undefined`，核心的声量采集从第一秒即失效。

当前版本改为由教师在教室电脑浏览器中选择本地图片作为“今日主角”。照片不再需要手机与教室电脑之间的配对或服务端中转，三款游戏也没有运行时服务端依赖。

## 决策

1. 使用 **Cloudflare Pages Free** 发布 Vite 生成的静态 `dist` 目录，并使用 Pages 提供的 HTTPS 地址或绑定的自有域名访问。
2. 图片只由浏览器本地文件选择器读取并处理；音频也只留在本机。部署不包含照片 API、配对码、数据库或对象存储。
3. 用 Service Worker 缓存本次构建资源，把“硬离线”降级为“抗断网”：首屏成功加载后，网络短暂中断时游戏仍可继续运行；刷新页面或首次访问仍需要网络。
4. NFR-01 正式修订为："首屏加载后应能在网络短暂中断时继续运行"，不再要求完全断网可用。

## 考虑过的替代方案

- **教室电脑本地服务（localhost）**：天然安全上下文、真离线，但需要教师维护本地运行环境，无法提供公共 HTTPS 地址。
- **公网 HTTP 直连**：麦克风直接拿不到，否决。
- **包含服务器照片中转的部署**：不再满足本地选图的隐私与简化目标，见 ADR-0002 的历史记录。

## 后果

- 正面：麦克风与 Service Worker 一并可用；发布不需要维护服务器；本地照片不会离开教室电脑。
- 负面：首次加载、刷新与更新依赖公网；教室应在课前确认能打开 Pages 地址并允许麦克风。
- 静态站点不能提供跨设备照片同步。若未来重新引入该需求，需单独评审服务端数据存储、访问控制与未成年人照片处理规则。
