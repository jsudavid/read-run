# 0002 · 照片经服务器内存中转、留存 1 小时（历史决策，已废弃）

> 状态：**已废弃，已被 ADR-0001 的 Cloudflare Pages 本地选图方案取代。** 本文仅保留历史背景，不代表当前产品行为，也不应作为部署依据。

- 状态：已废弃
- 日期：2026-09-25

## 背景

PRD v1.0 的 P3「音频不出本机」与 NFR-02 把"不上传、不留存"列为涉及未成年人的**硬约束**。

新需求要求"教师用手机拍照 → 教室电脑上作为主角"。手机与教室电脑是两台设备，其浏览器本地存储互不相通（同源策略），照片**必须经过一个中转**才能跨设备到达。产品方已明确：**先不纠结隐私**，照片上传前经学生同意，且软件在**无照片时也能正常使用**。

## 决策

1. 照片经**服务器内存中转**：手机上传 → 服务器内存留存，**TTL = 1 小时**，房间码窗口内任意次可取，到点删除。
2. 上传页设**显式同意确认**（勾选"已获得该学生同意"方可提交）。
3. **抠图与剪影化在浏览器端完成**：投影上只出现"剪影 + 主色调"，无面部细节、无姓名。
4. **音频仍严格不出本机**——本 ADR 只放宽照片，NFR-02 中关于音频的部分不变。

## 考虑过的替代方案

- **完全不经服务器（照片编码进房间码）**：服务器零接触照片，但码过长、手工不可用，违背 P6。
- **读取一次即删**：服务器留存时间更短，但无法满足"1 小时内任意次可取"的使用诉求。

## 后果

- 正面：配对流程对教师简单（扫码/输码）；实现直接；音频隐私红线不受影响。
- 负面：未成年人面部照片在服务器内存中最长驻留 1 小时，暴露面高于“数据不出本机”。属当时已知并接受的代价。
- 当前方案已改为浏览器本地选图和本地处理，不需要照片中转。若未来再次引入跨设备传图，必须新建 ADR 并重评数据保护要求。
